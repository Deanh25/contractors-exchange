Composer icons · mockup

Real icons, and a tooltip on every one

The composer currently uses emoji characters as buttons (📷), which render differently on every machine and read as content rather than controls. These are proper line icons in the LinkedIn / Facebook idiom, at one weight, each with a tooltip naming what it does. Same set everywhere the actions appear: the messenger, the feed composer, and comment composers.

Today · what it replaces

Why the current buttons have to go

Today
📷 one button, an emoji character, no label

An emoji glyph is drawn by the operating system, so it looks different on Windows, a Mac, and an Android phone, and it can never match a real icon set. Nothing tells you what it does until you click it.

Proposed
GIF

Four separate actions, one drawing weight, identical on every machine, each naming itself on hover. Photos and documents split apart, so the file picker only ever offers what you actually asked for.

Pick one

Three treatments of the same four icons

The icons are identical in all three; only the button around them changes. Hover each row to feel the difference.

My recommendation

A · Quiet ghost buttons

No chrome until you hover, then a soft grey pad. Exactly what LinkedIn and Messenger do, and it keeps the eye on the message.

Option

B · Brand tint on hover

Same shape, but hovering washes the button in CX orange. More clearly ours; slightly busier when four sit in a row.

Option

C · Always-visible chips

Each icon sits in a permanent grey chip. The most obviously clickable, but it puts four grey blocks under every message box.

Two things to decide, and one you should know about

These icons come from lucide, which CX already uses for the feed reactions and comment controls, so this makes the whole app one icon family instead of emoji in some places and icons in others. The same four go into the feed composer and comment boxes, not just the messenger.

GIF is not a feature we have. The icon is easy; the capability behind it is not. A GIF button means searching a library like Giphy or Tenor, which is an external service with an API key and its own terms. So it is really a small new feature, and I would build the other three now and treat GIF as its own task once you confirm you want it.

Tell me: (1) A, B, or C? (2) GIF now, or the other three first and GIF as its own task? Then I will roll the set out everywhere, with a tooltip on every one, per the rule you set.
